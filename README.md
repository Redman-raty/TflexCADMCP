# T-FLEX CAD ↔ MCP

C#-плагин для T-FLEX CAD 18 и Python-сервер MCP через stdio. Сборки проверены по DLL, XML и StarsPlugin из установки 18.0.56.0. Плагин собирается под .NET Framework 4.7.2, AnyCPU, с Copy Local = False для библиотек САПР. Состояние модели читается и изменяется в UI-потоке. Локальный Windows Named Pipe доступен пользователю, запустившему САПР, в той же Windows-сессии.

В учебной редакции **18.0.56.0** используйте штатный макрос в отдельном GRS. Он открывает локальный именованный канал для MCP. В редакциях с поддержкой внешних приложений можно загружать плагин TFA. Поиск по XML работает без запущенной САПР. [Ограничения учебной редакции](https://www.tflexcad.ru/download/t-flex-cad-free/limitations.php)

## Локальная настройка

В PowerShell из корня репозитория выполните команды ниже. В `.env` задайте фактический путь к установленной САПР.

```powershell
Copy-Item .env.example .env
notepad .env
.\scripts\load-env.ps1
python -m venv artifacts\venv
.\artifacts\venv\Scripts\python.exe -m pip install -r server\requirements.txt
```

`load-env.ps1` передаёт настройки в текущий процесс PowerShell и его дочерние процессы. Запускайте его в каждом новом окне перед сборкой или ручным запуском сервера. Для MCP-клиента настройте его конфигурацию по одному из примеров: [плагин TFA](mcp.example.json) или [учебный макрос](mcp.education.example.json). Замените пути на абсолютные пути своей установки и копии репозитория.

## Учебная редакция

Для новой копии репозитория сначала соберите исходник макроса и создайте его GRS по инструкции в конце этого раздела.

1. Откройте в установленной учебной T-FLEX файл `artifacts\education\McpEducation.grs`. В панели **Макросы** раскройте имя документа и дважды щёлкните **Start**. Оставьте документ открытым, затем переключитесь на нужную модель или вызывайте создание чертежа. **Stop** прекращает приём запросов.
2. Подключите MCP-клиент по [mcp.education.example.json](mcp.education.example.json). В учебном режиме доступны прежние пять инструментов и `create_drawing`. В пакетном режиме доступны `check` и `stl`.
3. Для тестового чертежа запустите команду ниже. Она создаёт редактируемый GRS, два эскиза листов PNG и отчёт в `artifacts\education\drawings`.

```powershell
.\artifacts\venv\Scripts\python.exe -X utf8 .\tests\education_check.py
```

`create_drawing` принимает `output_dir` и `drawing.sheets`. Каждый лист задаёт имя, размеры в мм и список элементов. Поддерживаются отрезки, полилинии, окружности, дуги через три точки, текст и ассоциативные линейные размеры. Размер связывается с узлами контура при совпадении координат. Листы строятся по заданным 2D-координатам, включая разрезы, описанные в задании. Образец содержит вид сверху и условный разрез опорной плиты. Автоматическое получение проекций из 3D-модели в этот сценарий пока не входит.

Сквозной прогон на учебной 18.0.56.0 создал 105 элементов на двух листах и проверил шесть размерных значений. MCP повторно прочитал созданный GRS и получил оба листа как `image/png`. Также проверены длина блока 100 → 120 → 120 после отката → 130 мм и пакетный экспорт двух STL. Хеши двух исходных файлов сравнили до и после экспорта.

Для пересборки исходника макроса запустите `scripts\build-education.ps1`. В пустом GRS в штатном **Редакторе макросов** добавьте C#-модуль с содержимым `artifacts\education\McpEducation.cs`. Добавьте системные ссылки `System.Core`, `System.Drawing`, `System.Web.Extensions` и `System.Windows.Forms`. Скомпилируйте через **Ctrl+F7** и сохраните GRS. Объекты CAD создаются и читаются в UI-потоке. Макрос запускается явно, выполняет только известные команды и не принимает исполняемый код.

## Сборка и подключение плагина TFA

Подготовьте Python 3.10+ с SQLite FTS5, MSBuild из Visual Studio Build Tools и targeting pack .NET Framework 4.7.2. Выполните команды в PowerShell из корня проекта.

```powershell
.\scripts\load-env.ps1
.\scripts\build.ps1
```

Укажите фактический корень установки через `TFLEX_HOME` или `-TFlexHome`. Для SDK доступны `TFLEX_SDK_DIR` и `-SdkDir`. Если задан только путь к SDK, корнем установки считается его родитель. Скрипт автоматически использует эталонные сборки из `artifacts\net472\build`, если они там распакованы. Для другой папки передайте `-ReferenceRoot <папка пакета>\build`. Для отдельного XML укажите `TFLEX_API_XML` и поместите одноимённую DLL рядом, чтобы получить версию из её ресурса. [Пакет эталонных сборок .NET 4.7.2](https://www.nuget.org/packages/Microsoft.NETFramework.ReferenceAssemblies.net472/1.0.3)

1. В поддерживающей плагины редакции T-FLEX откройте **Начало работы → Приложения → Добавить… → …**. Выберите папку `plugin\bin\Release`, содержащую `TFlexMcp.tfa` и `TFlexMcp.dll`.
2. Добавьте **T-FLEX MCP Bridge**. Если приложение появилось со статусом «Не запущено», выделите его и нажмите **Запустить**, затем закройте диалог.
3. Скопируйте запись из [mcp.example.json](mcp.example.json) в конфигурацию клиента и задайте абсолютные пути к Python, серверу и нужной установке. Команда запуска сервера в режиме stdio приведена ниже. Обычно её выполняет сам MCP-клиент.

```powershell
.\artifacts\venv\Scripts\python.exe .\server\tflex_mcp.py
```

Один экземпляр САПР использует канал по умолчанию. Для отдельных экземпляров при запуске САПР и соответствующего MCP-сервера задавайте одинаковое уникальное `TFLEX_MCP_PIPE_NAME`. Тайм-аут вызова задаёт `TFLEX_MCP_TIMEOUT` в секундах. После тайм-аута изменения повторно прочитайте модель, поскольку САПР могла закончить вызов после отключения клиента.

## Инструменты

| Инструмент | Вызов и результат |
| --- | --- |
| `search_tflex_api` | `query="Document.EndChanges"`. Локальные `TFlexAPI.xml` и `TFlexAPI3D.xml`, идентификаторы членов, параметры и версия DLL. База FTS5 автоматически обновляется в `.tflex-mcp`. |
| `get_document_state` | Идентификатор активного документа на время его открытия, значения и выражения переменных, операции с прямыми зависимостями и габаритами в метрах, листы, открытые виды и диагностика. Причины недоступности значений и габаритов указаны в ответе. |
| `set_variables` | `document_id` из свежего состояния, `variables={"L":"120"}`. Один блок изменений без автосохранения. Ответ содержит результат перестроения и итоговые значения. |
| `batch_process_files` | `files` с абсолютными локальными путями к `.grs`, `scenario="check"`, `"stl"`, `"step"` или `"dxf"`, абсолютный `output_dir`. В каждой задаче создаётся новая подпапка. `check` сохраняет JSON состояния с перечнем найденных ошибок переменных и операций. `files[].ok` показывает, выполнился ли сценарий для файла. |
| `capture_viewport` | `view_name="3D"` для активного или единственного открытого 3D-вида, `"3D:1"` по списку текущих видов, название листа или его `sheet:<id>`. Клиент получает блок MCP `image/png` и сведения о выбранном виде. |

## Проверка

```powershell
.\scripts\build.ps1 -WithFixture -WithTransportCheck -ReferenceRoot .\artifacts\net472\build
.\artifacts\venv\Scripts\python.exe -X utf8 .\tests\mcp_check.py
.\artifacts\venv\Scripts\python.exe -X utf8 .\tests\mcp_check.py --transport
```

Первый запуск тестирует stdio, пять инструментов, локальный поиск и ошибку отсутствующего плагина. `--transport` запускает C#-стенд с тем же каналом и диспетчером UI, проверяет крупный UTF-8 ответ, структурированную ошибку, PNG в MCP и повторный вызов.

Для живого теста в редакции с поддержкой приложений добавьте отдельно **T-FLEX MCP Test Fixture** из `tests\fixture\bin\Release`, запустите его и закройте диалог приложений. Тестовый плагин создаёт две исходные модели и открывает `mcp-block-working.grs` в подпапке `fixtures`. Для повторного прогона заново откройте сохранённую рабочую модель с `L=100` и запустите клиент.

```powershell
.\artifacts\venv\Scripts\python.exe -X utf8 .\tests\mcp_check.py --fixtures .\tests\fixture\bin\Release\fixtures
```

Тест проверяет габарит твёрдого тела при `L=100`, `L=120`, после отката ошибочного блока и при следующем `L=130`. Также проверяются две выгрузки STL, неизменность исходных файлов и получение двух PNG клиентом. Для проверки других форматов предусмотрены `--format step` и `--format dxf`.

Для автономной проверки Open API в учебной редакции выполните `scripts\prepare-native-check.ps1`. В отдельном пустом 3D-документе откройте **Инструменты → Редактор макросов**, добавьте C#-модуль и вставьте содержимое сгенерированного файла. Добавьте ссылки `System.Core`, `System.Windows.Forms` и `System.Drawing` в меню **Проект → Добавить ссылку**, скомпилируйте через **Ctrl+F7** и запустите `Run` в окне **Макросы**. Результаты сохраняются в `artifacts\native-check`. Для нового прогона передайте пустую папку через `-OutputDir`.

В установленной учебной редакции автономный тест измерил длину 100 → 120 → 120 после отката → 130 мм. Проверены два двоичных STL из файлов, открытых для чтения, и два PNG. Модели, выгрузки и протокол прогона находятся в `artifacts\final-test`. Проверьте передачу этих PNG в MCP на стенде командой `tests\mcp_check.py --transport --images artifacts\final-test` через Python из виртуального окружения.

STEP и DXF собраны по API 18.0.56.0 для режима TFA. Их экспорт, PDF и спецификации остаются непроверенными. Сквозной прогон в этой установке выполнен через макрос. MSBuild выдаёт MSB3270 для заданного AnyCPU и x64-библиотек САПР.

## Эксперимент с Roslyn

Штатный MCP публикует пять инструментов. Для эксперимента запустите отдельную тестовую сессию CAD с поддержкой плагинов и подготовьте задание вручную.

```powershell
.\scripts\prepare-trusted-job.ps1 -Enable -Script .\experiments\ExampleScript.cs -Files 'C:\test\a.grs','C:\test\b.grs' -ReferenceRoot .\artifacts\net472\build
```

Скрипт должен реализовать `public static void TrustedJob.Script.Run(Document)`. MSBuild вызывает Roslyn один раз на задание, а подготовка копирует GRS в его папку. Загрузите вручную **T-FLEX MCP Trusted Scripts** из `experiments\bin\Release`, вызовите **Run trusted CAD job** и выберите созданный `job.txt`. Одна сборка используется для всех копий, результат записывается рядом в `result.json`. Код выполняется в процессе CAD с правами пользователя. Запускайте только доверенный исходник.
